# CycleCode 0.1.0-preview.7

Release date: 2026-11-15

**Guided Work Items, simpler document review, and direct prototype editing.**

This preview brings a continuous, approval-gated Work Item process, a shared document viewer, automatic prototype checks, and clearer implementation failure handling.

Changes since `release/0.1.0-preview.6`:

## Work Items And Agent Coordination

- Choose **Manual** or **Semi-auto** per Work Item. Semi-auto continues clarification, analysis, design and task preparation, stopping at approval gates before development. The choice is saved per task; switching back to Manual lets the current step finish before stopping.
- Follow the current stage from a single **Next step** panel with task documents, relevant role conversations and a visible Stop action for an owned run.
- Added durable process progress, attributed questions and answers, saved dispatch records and restart recovery. Uncertain execution remains blocked instead of being treated as completed.
- Added managed Developer, Reviewer, QA and bounded repair paths, candidate-specific acceptance and local Git completion records. These backend capabilities do not make unrestricted automatic execution available.
- Simplified stage instructions and role navigation. Task-originated chat instructions show their Work Item source, and open conversations follow role turns started by the process.
- **Auto for an individual Work Item remains disabled.** The proposed project-level **Build the application** button is not included in this release.

## Documents And Architecture

- Product Definition uses document cards with a common viewer for reading, editing, versions and approval. Plan documents and Architecture documents use the same shared viewing surface.
- Architecture now presents **Overview**, **Modules** and **Decisions** together, with expandable card sections and a module dependency dialog.
- Dependency arrows come from saved module references; missing documents and cycles are visible. Older modules without dependency metadata do not acquire inferred dependencies.
- Consolidated document toolbars and dialog controls, including generation actions and consistent close buttons.
- Architect can explicitly confirm that a task's existing design needs no revision. Architecture generation records its PRD lineage through the host.
- System discussion topics are hidden by default and can be revealed with **Show system topics**.

## Prototype Review And Editing

- Completed Designer changes create a version automatically. When the Prototype screen is open, finalized versions without a report are checked automatically.
- Failing checks can trigger up to **three** Designer repair attempts before the flow asks for user input.
- Review focuses on the preview, **Accept prototype**, and comments in chat. Versions, checks and manifest details open in compact popups.
- **Accept anyway** is available for an eligible version with failing checks after explicit confirmation; the failed report and override remain recorded.
- Pick an element in the desktop preview and ask Designer for a targeted change. Added element editing tools for bounded modifications.

## Implementation And Validation

- Run Profiles can declare coupled files, such as a manifest and its lock file. Task preparation derives the permitted companion files, and execution can return synchronization feedback to the same agent session.
- Eligible dependency-install failures and mandatory-check failures can receive one automatic follow-up under the existing scope and repair limits. This can start another provider run and incur provider charges; it is not an unlimited retry loop.
- Failure summaries distinguish agent failures, dependency preparation, scope violations, Git state changes and validation failures.
- Git staging alone no longer makes an otherwise permitted edit a scope violation. HEAD or branch changes remain separately checked.
- Added a mandatory application-start check for eligible prepared candidates with an approved RUN profile. UI/hybrid checks require an HTML response as well as readiness; this is a process/HTTP check, not a browser-render test. Older task packages may require **Update task**.

## Setup, Providers And Desktop

- Clearer first-project guidance on Home and in the setup wizard, starting from one checked AI connection and a small idea.
- Provider data-sharing confirmation is requested when adding the destination rather than repeatedly during ordinary stage launches. Review the destination and permissions before accepting.
- Web search and web-page access are enabled by default for Discovery, Product Analyst, Project Manager and Architect where the selected provider supports them. **The upgrade also enables these groups for existing built-in routes and roles.** Review Routing if you want them disabled.
- Improved Antigravity session resumption and retirement of sessions with outdated MCP commands.
- Fixed a blank macOS setup sheet that could block interaction. Platform availability depends on the attached application packages.

## Upgrading To Preview.7

1. Back up and verify your CycleCode profile before upgrading, and back up source repositories separately. Keep the backup for rollback: preview.6 must not open a profile migrated by preview.7.
2. Download an application package from the official [Releases](https://github.com/cyclecode-labs/releases/releases). GitHub source archives are not installers. Updates remain manual.
3. **Preview.6 profiles are the supported upgrade source.** Their recorded schema history is adopted before the new migrations run; existing project data is retained.
4. **Preview.5 and older:** open the profile once in preview.6 before upgrading, or start with a new profile. Direct opening in preview.7 is refused.
5. **Unreleased development profiles with the old, unsquashed migration history beyond preview.6 are refused.** Create a new profile; do not edit migration history by hand. Intermediate preview.7 profiles whose applied migration checksum predates the final release squash also require a new profile.
6. Review the web-tool defaults under Routing, and use **Update task** when an older prepared task lacks the current mandatory checks.

See [installation and updates](../INSTALL.md) and [data and backups](../DATA-AND-PRIVACY.md).

## Preview Status

This remains an experimental preview. Automated checks and successful packaging do not establish complete installed-app, real-provider or cross-platform qualification. Full automation remains unavailable in the UI. The one-button project build is planned, not delivered. Push and deploy remain outside this release's automatic local workflow.

Use only the platform assets attached to the release. Windows development packages are unsigned and labeled `UNSIGNED_DEVELOPMENT_BUILD`; review the installation notes before running them. No signing or macOS qualification is implied by the release notes.

Report bugs in [GitHub Issues](https://github.com/cyclecode-labs/releases/issues). Include `0.1.0-preview.7`, operating system, reproduction steps, and expected and actual behavior. Remove credentials and confidential project content first.
