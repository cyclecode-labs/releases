# CycleCode 0.1.0-preview.8

Release candidate prepared: 2026-11-18. Publication date is set when the release is published.

**More reliable document generation, clearer traceability, and stronger requirement coverage.**

This preview improves the path from Discovery to a reviewable plan. It gives models bounded opportunities to correct ordinary mistakes, makes saved source relationships easier to read, and adds checks that keep Discovery notes and story requirements connected to downstream documents.

Changes since `0.1.0-preview.7`:

## Document Generation And Recovery

- Generation can repair malformed, schema-invalid or rejected output within the same run: one initial attempt and at most two repairs. Only a validated result is published. Provider failures, cancellation and timeouts remain failures.
- Repair feedback points to invalid fields, accepted source identifiers and JSON parse locations. Runs that fail output validation retain bounded problem details for diagnosis.
- Document-authoring turns can continue when an agent ends without saving the required draft or asking a structured question. Continuation remains bounded; it does not approve documents or waive required inputs.
- A complete model answer missing only closing JSON brackets can be repaired before parsing. This does not recover arbitrarily truncated output.
- Tool refusals give more actionable feedback. Document text that declares its own approval status is refused; approval remains a host-controlled action.
- Discovery uses project context more consistently. Vision language is checked against its Discovery on both authoring and generation paths.

## Sources, Documents And Planning

- Saved Discovery documents must account for the active notes in their discussion. Requirement, constraint and decision notes become individually traceable source items; Vision must cite every such item.
- Acceptance Criteria explicitly name the requirements they cover. Finishing criteria checks coverage of the requirements linked by their Stories; Plan exposes requirement coverage alongside story and criterion coverage.
- Stories link to Architecture modules and ADR document items. Source labels and Work Item briefs use document and task titles more consistently, and briefs narrow their listed sources to the task.
- Chat-written Architecture, ADR and backend specification sources carry the lineage needed by downstream generation. Architecture and ADR saves require summaries; module dependency metadata is persisted correctly.
- Vision and Stories are easier to read without inline internal identifiers. Architecture source selection and member labels show document titles.
- Stage indicators refresh after writes. A proposed plan counts as applied only after it is applied.

## Prototype Validation

- Input-dependent prototype navigation must be demonstrated by a passing interaction flow.
- Failed prototype checks can be sent back to Designer with their results for bounded repair.
- Prototype revisions made without a new PRD keep their predecessor's lineage.

## Preview Validation And Known Limitations

This is an experimental preview. Earlier Windows runs completed the backend document cycle with Claude Code Haiku and, after tester question-handling repairs, Codex Terra. Other campaign paths stopped or remained pending in the recorded validation. Those runs used earlier packaged revisions; they do not qualify every change in this candidate or prove the complete idea-to-implementation/merge/deploy workflow.

- **API-key plugin setup is currently blocked in the desktop app (CC-GF-201).** Saving a plugin secret slot for providers such as `anthropic-api`, `openai-api` or `gemini-api` returns `SECRET_STORE_UNAVAILABLE`. This is a known defect, not a credential-entry mistake. CLI-provider paths used by the recorded document-cycle runs are separate; this candidate has not repeated their real-provider runs.
- Some prior runs recorded 404/409 responses during document generation or source resolution despite successful saves. Source navigation and remaining presentation issues are not fully qualified.
- Auto for individual Work Items remains unavailable; the one-button project build remains planned. Approval gates still apply. Push and deploy remain outside the automatic local workflow.
- Windows packages are unsigned and labeled `UNSIGNED_DEVELOPMENT_BUILD`. NSIS installation, upgrade/uninstall on a clean machine, macOS, repo import and full real-provider regression have not been qualified for this candidate.

## Upgrading To Preview.8

1. Create and verify a profile backup, and back up source repositories separately. Keep the backup for rollback; do not reopen a migrated profile in an older preview.
2. Download the Windows x64 installer or portable application asset from the release. The package includes the application Java runtime; project build tools are installed separately. GitHub source archives are not installers.
3. Released preview.7 profiles apply the preview.8 migration while retaining project data. Preview.6 profiles can also upgrade directly through the retained migration chain.
4. Preview.5 and older must first open the profile with preview.6, or start with a new profile.
5. Intermediate development profiles using the former preview.8 V094–V096 migrations must be recreated. Old pre-squash development profiles remain unsupported. Do not rewrite migration history manually.
6. Review Routing and refresh older prepared tasks with **Update task** when required checks are outdated.

Updates remain manual. See [installation and updates](../INSTALL.md) and [data and backups](../DATA-AND-PRIVACY.md).

Report problems in [GitHub Issues](https://github.com/cyclecode-labs/releases/issues). Include `0.1.0-preview.8`, OS, reproduction steps, and expected and actual behavior. Remove credentials and confidential content first.
