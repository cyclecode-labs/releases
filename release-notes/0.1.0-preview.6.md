# CycleCode 0.1.0-preview.6 — Connected Planning, Run Controls & Guided Repair

CycleCode preview.6 makes planned work easier to trace and projects easier to run. This release adds a connected Plan overview, editable project run profiles, guided repair for failed application runs, per-project agent choices, and document authoring directly in role chats.

Changes since `release/0.1.0-preview.5`:

## Planning And Work Items

- Redesigned **Plan** around three connected steps: **Stories → Acceptance Criteria → Work Items**.
- Added a coverage table and story detail view to show which criteria and tasks cover each story, with filters for gaps.
- Added story import from repository files or pasted text, visible source provenance, configurable tracker story types, and confirmed links between tracker work and internal planning items.
- Added a stories-first planning path for projects with existing requirements. Architecture approval remains required for criteria and Work Item planning.
- Improved plan revisions: explicitly confirmed stale plans retain their pinned inputs, and applying a revised plan preserves the title and goal of tasks already started.
- Simplified Work Item pages with stage-ordered role tabs, clearer task details, criterion status chips, compact history, and easier access to the next action.

## Project Run Profiles And Controls

- Moved run profiles into **Project Settings** as versioned configuration, separate from Architecture documents.
- Added Architect-proposed profiles with explicit approval, plus direct editing of commands and host tools.
- Added an app-bar profile switcher for running and testing the current workspace, with restart, stop, readiness status, and output.
- Reduced output clutter by retaining only the latest ordinary run for each profile.
- Made approved project test profiles mandatory checks for newly prepared development and repair candidates.
- Added dependency preparation from approved INSTALL profiles, including reinstallation when implementation changes dependency inputs.

## Guided Repair For Failed Runs

- Added **Repair** for eligible application startup failures, including processes that exit before becoming ready.
- The Architect can diagnose the failure and propose a structured repair plan covering profile changes and scoped code changes.
- Repair presents commands and scope for approval, prepares an isolated candidate, and records verification results for review and acceptance.
- Fixed acceptance of code repairs and merging of eligible worktree results.
- Improved failure explanations, readiness diagnostics, and repair-result handling.

## Agents, Documents, And Settings

- Added per-project provider and model overrides for roles.
- Enabled built-in roles to create and revise their own project document types directly in chat when instructed. Saved drafts still require the applicable approvals.
- Added readable document titles and improved document presentation.
- Refined role instructions and repository document attachment support.
- Updated Claude Code integration to append role instructions to its default system prompt.
- Improved Antigravity reporting of tool identifiers and failed tool steps.

## Desktop Reliability

- Enabled automatic update checks by default in all builds, while preserving saved preferences. Installation remains manual.
- Improved packaged backend startup diagnostics and startup from profile directories reached through filesystem links.
- Improved macOS build resilience with Electron download caching and retries.

## Upgrading From Preview.5

- Back up your CycleCode profile before upgrading. This release changes the local database schema; preserve the backup for rollback.
- Download the application package for your platform from the official [Releases](https://github.com/cyclecode-labs/releases/releases). Availability and platform support depend on the attached application assets; GitHub source archives are not installers.
- **Existing Project Baseline documents do not migrate into run profiles.** Ask the Architect to propose run profiles again, then approve them in chat or under **Project Settings → Run profiles**.
- Use **Update task** to refresh older prepared task packages when CycleCode reports missing or outdated project test checks.

## Preview Status

This remains an experimental preview. Manual workspace runs do not count as Work Item acceptance evidence. Guided repair still requires installed-app and real-provider end-to-end qualification; targeted automated checks do not establish complete release qualification.

Report bugs and suggestions in [GitHub Issues](https://github.com/cyclecode-labs/releases/issues). Include `0.1.0-preview.6`, your operating system, reproduction steps, and expected and actual behavior. Remove credentials and confidential project content from screenshots and logs.
