# CycleCode 0.1.0-preview.5

CycleCode preview.5 expands the path from product definition to accepted code and a reviewable release package. It adds task planning with dependencies, external task intake, richer agent conversations, local backup and recovery, and a dedicated Delivery page.

This is an experimental preview. Updates remain manual. Availability and platform support depend on the application assets attached to the [GitHub release](https://github.com/cyclecode-labs/releases/releases/tag/0.1.0-preview.5).

## Highlights

- **Plan connected work.** Generate and edit a draft task plan, inspect its dependency graph, and create Work Items when the plan is ready.
- **Bring in tracker tasks.** Preview assigned GitHub.com issues and Jira Cloud tasks, then adopt selected work into a project.
- **Share context with agents.** Attach images and text files to conversations, answer clickable agent questions, and export documents and chats as Markdown or HTML.
- **Review and accept code.** Inspect diffs, scope findings, validation evidence, and saved Git results; acceptance can merge eligible results into the original branch.
- **Prepare a project release.** Build declared outputs from a selected commit, review the evidence, approve the package, and export it from Delivery.
- **Protect local project data.** Create and verify profile backups, then restore with explicit confirmation and a restart.

## What Changed Since Preview.4

### Planning And Work Items

- Added dependent Work Item planning after User Stories and Acceptance Criteria, with a modal generation view and a laid-out dependency graph.
- Separated the editable draft plan from created Work Items. Proposed tasks can be edited in dialogs before creation.
- Unified task preparation and blocked stage starts until predecessor tasks are accepted.
- Made task actions and review decisions easier to reach, added a collapsible Task brief, and highlighted active tasks on the dashboard.
- Added reusable diff review and scope review with a repair flow. Repair warns when the current coding-agent route cannot continue the session.
- Changing the coding agent starts a new Developer session instead of resuming the previous agent's session.
- Retained attempt Git results and exposed their branch and commit information on the Work Item.
- Accepting an eligible in-place result now attempts a merge into its recorded original branch. A failed merge remains visible and can be retried; acceptance and merge status are separate. `WORKTREE` attempts do not support this automatic merge path.

### Delivery

- Replaced **Review And Delivery** with a dedicated **Delivery** page for project releases. Attempt-level diffs, scope evidence, risks, and the optional merge-ready PR package are available on the Work Item; execution history remains in Runs.
- Added a release preview with the target branch and commit, included Work Items, other commits, and warnings about incomplete or unmerged work.
- Added builds in a detached worktree using the approved project Baseline's `INSTALL`, `BUILD`, `TEST`, and `LINT` profiles. Build profiles must declare their output paths.
- Added per-step logs, build history, explicit approval of the package manifest, and verified export of outputs, logs, `release-manifest.json`, and `DEPLOY.md`.
- Fixed release preview loading to read every Work Item rather than requesting a page larger than storage permits.

Delivery prepares a local package. It does not push code, create tags, upload assets, deploy an application, or start `RUN` profiles.

### GitHub And Jira Cloud

- Added secure connections for GitHub.com using a personal access token and Jira Cloud using site, email, and API token.
- Added assigned-task projections, a **From trackers** board column, read-only task previews, and explicit adoption of source content into local work.
- Added a shared connector foundation for external task intake.

These integrations do not write back to remote issues. GitHub Enterprise, Jira Data Center, and OAuth connection flows are outside this preview's intake support.

### Conversations And Agent Runs

- Added durable agent questions with clickable suggested answers and a custom-answer flow. Superseded questions are tracked so stale answers cannot authorize newer work.
- Added managed conversation attachments through paste, file selection, and drag and drop, including attachment-only messages. Supported inputs include PNG/JPEG/WebP images and bounded UTF-8 text/source/configuration files.
- Added native image input for Codex CLI and supported model-provider transport. Native image transport is not implemented for Claude Code or Antigravity.
- Simplified the chat composer and updated role avatars.
- Reworked Runs to show the failure cause first, group the attempt timeline, display turn progress, and provide Retry and turn-limit continuation actions.
- Added per-role turn limits, removed fixed aggregate cutoffs that interrupted active turns, and journaled decoded agent events instead of raw stream lines.
- Rendered diagnostic messages and the agent's last messages with the shared Markdown renderer.

Conversation attachments are limited to 8 files, 5 MiB per file, and 20 MiB per message. Text extraction is also bounded. PDF/OCR, Office documents, and archives are not supported.

### Documents And Readable Export

- Added filesystem snapshot exports for documents, conversations, Work Items, and projects in Markdown, HTML, or both. HTML conversations use a styled dialogue layout.
- Redesigned the document catalog and added a native file picker for local document references.
- Added read-only local Markdown/plain-text attachments to the common document catalog and manual repository onboarding. Explicit source checks and refresh preserve previous saved versions.
- Replaced free-text document scope with explicit project or task scope.

Local document references accept strict UTF-8 `.md`, `.markdown`, and `.txt` files up to 128 KiB. Source changes require an explicit check or refresh; there is no automatic synchronization or external file editing. Readable exports are snapshots, with no reverse synchronization.

### Setup, Project Environment, And Local Data

- Added a modal first-launch setup wizard for provider connections, role assignments, optional MCP configuration, and readiness checks, with styling consistent with the application.
- Added project Baselines and run profiles, a Project bootstrap Work Item, and Windows environment checks.
- Added profile disk-usage reporting, manual backup creation, backup inventory, verification, and restore with safe restart and interrupted-switch recovery.
- Added the foundation for capturing a raw local Git baseline. Execution from that baseline and applying its results remain subsequent work.
- Added GitHub release discovery, an update indicator beside the logo, and **Settings → Updates** with channel selection and scheduled-check preferences. Installation remains manual.
- Required explicit acceptance of bundled license and preview terms in packaged applications, fixed the startup handoff after acceptance, and added a Help license viewer.

### Agent And Repository Handling

- Bounded Claude Code native file-tool access to the working directory.
- Replaced Antigravity's permission-bypass flag with generated per-launch permission settings. A live CycleCode turn was reported successful by the operator; not every native-tool/version combination has been qualified.
- Fixed restoration of in-place attempts to exclude generated output ignored only by the attempt's own ignore rules.

## Installation And Upgrade

1. Close the previous CycleCode version and back up your existing profile and source repositories. Default Windows locations are `%LOCALAPPDATA%\CycleCode\profile` for project data and `%APPDATA%\CycleCode` for desktop settings and protected credential storage. Custom locations can differ.
2. Download the application package for your platform from the official release assets. GitHub's generated source archives are not application packages. Check the published SHA-256 value when provided.
3. On Windows x64, run the setup executable, or launch the portable executable if one is supplied. Portable packaging does not make the profile portable: it uses the configured local profile locations.
4. Launch CycleCode, accept the bundled terms when requested, and review provider and coding-agent readiness. First-time users can follow the setup wizard.

The application package includes its Java runtime. Git and project-specific build tools must be installed separately. Provider credentials, accounts, and external coding-agent authentication remain your responsibility.

Unsigned assets are labeled `UNSIGNED_DEVELOPMENT_BUILD` and may trigger Windows publisher or SmartScreen warnings. Preview.5 changes the local database schema; do not assume an older version can reopen an upgraded profile. Preserve a pre-upgrade backup rather than relying on downgrade compatibility.

## Known Limitations And Qualification

- **Experimental release:** focused automated checks and some isolated Electron/live checks are recorded for individual changes. The complete preview.5 installer and end-to-end workflow have not been qualified by this release-note preparation. Existing validation records include broader Java and UI suite failures; this is not an all-green release certification.
- **Delivery:** a complete real-project `npm`/`mvn` release build, approval, and export in the installed application remains unqualified. Release builds require a usable Git repository, approved Baseline, completed bootstrap, declared build outputs, and available tools. They do not inject credentials; private registry access may require repository configuration. `INSTALL` can use the network, and builds are not isolated by an OS sandbox.
- **Git acceptance:** installed-app automatic merge, conflict, dirty-checkout, and busy-checkout cases are not fully qualified. Git 2.38 or newer is required for the merge path. A conflict may require a manual merge before retrying the recorded merge action.
- **Backups:** local folders are unencrypted and exclude repositories, worktrees, credentials, logs, caches, and external CLI history. Finish active agent work before creating a backup. Restore supports the same profile location and current compatible schema; migration to another machine/location is not provided. Scheduling and automatic retention are not implemented.
- **Update checks:** discovery opens the official release page; it does not download or install an update. A published announcement may have no compatible installer yet.
- **Platform and provider coverage:** Windows is the primary documented installation path. Do not infer macOS/Linux or every real provider/CLI combination is qualified from the presence of packaging code or unit tests. Use only the packages and platform instructions actually attached to the release.
